# 학생맞춤통합지원 관찰관리 앱 구현 계획 (3차 · UI 시안 반영)

교사가 일과 중 학생의 누가 관찰 기록을 빠르게 남기고, 나중에 분야별로 모아 보는 앱.
디자인은 별도로 제공받을 예정이므로 이 문서는 구조·기능·데이터·개발 순서에 집중한다.

## 0. 3차 변경 요약 (UI 시안에서 추가된 요구)

- 학교 구조: 과 → 학년 → 반. 명단 편집은 행정담당자만, 교사는 조회.
- 역할 4종: 담임교사, 분야 담당(상담·복지·보건), 교과교사, 행정담당자. 기록마다 그때의 역할을 T 배지로 표시.
- 기록별 공개 범위: 작성자가 "교사 전체" / "담당 교사만"을 직접 선택. 분야에 따라 자동으로 잠기지 않는다.
- 잠긴 기록 열람: 해당 학생의 담임, 작성자, 상담·복지·보건 전담 계정만. PIN 6자리로 해제하며 12분 뒤 자동 잠금. 해제·열람은 열람 로그에 기록.
- 작성 전 안내 모달(사실 중심 기록, 민감정보는 비공개 저장)에 동의해야 작성 시작.
- 자주 쓰는 문장: 분야를 고르면 해당 분야 문장이 표시되고 누르면 본문에 추가.
- 홈: 위기 알림(문제행동 3주 연속, 장기 미기록)을 가장 위에, 오늘 기록, 잠긴 항목은 배지만.
- PC: 좌측 메뉴(대시보드·기록 목록·학생 명단·교사 명단·통계·통합지원 회의·설정), 통계 타일, 최근 기록 표, 분야별 분포.
- 태그 기본값에 "진로" 추가.
- 통합지원 회의: 안건 학생 선정, 학생별 기록 요약, 회의록, 결정 사항 추적, 회의 자료 내보내기까지 구현. 회의 내용 열람은 작성자·전담·행정·안건 학생 담임으로 제한.
- 음성 받아쓰기는 제외하기로 확정.
- 구현 완료 범위와 사용법은 README.md, 배포는 docs/배포안내.md 참고.

## 1. 확정 사항

| 항목 | 결정 |
|---|---|
| 개인정보 | 학생 실명·학년·반·번호 저장 |
| 저장 위치 | Google Sheets에 동기화 (단일 시트, 학교 계정 소유) |
| 사용자 | 교사 약 100명이 동시에 사용. 같은 학생에 동시에 기록해도 꼬이지 않아야 함 |
| 기기 | 휴대폰·PC 모두 (반응형) |

## 2. 전체 구조

```
[교사 브라우저]  ──HTTPS──▶  [Google Apps Script 웹앱]  ──▶  [Google Sheet]
 정적 웹앱(HTML/CSS/JS)        시트 소유 계정으로 실행          학생 / 관찰기록 / 태그 / 교사 / 로그
 GitHub Pages 배포, PWA        잠금·검증·권한 처리
```

- **프론트엔드**: 빌드 도구 없는 정적 웹앱. GitHub Pages에 올리고 휴대폰 홈 화면에 추가(PWA)해 앱처럼 사용.
- **백엔드**: 시트에 연결된 Google Apps Script를 웹앱으로 배포. 모든 읽기·쓰기는 이 스크립트를 거친다.
  교사는 시트를 직접 열 수 없고, 시트 소유 계정(학교 업무 계정)만 접근한다.
- **오프라인 대비**: 저장 실패 시 브라우저에 임시 보관했다가 자동 재전송.

## 3. 동시 저장 안전 설계 (핵심)

100명이 같은 시각에 같은 학생 기록을 저장해도 데이터가 겹치거나 사라지지 않도록 다섯 겹으로 보호한다.

1. **기록은 추가만, 덮어쓰기 없음**
   - 모든 기록은 시트에 한 행씩 추가된다. 기존 행을 고쳐 쓰지 않으므로 두 교사가 같은 학생에 동시에 기록해도 두 행이 각각 남는다.
   - 기록 ID는 브라우저에서 만든 고유값(UUID). 서버는 같은 ID가 이미 있으면 무시하므로, 재전송돼도 중복 저장되지 않는다.

2. **서버 잠금**
   - Apps Script의 LockService로 쓰기 작업을 한 번에 하나씩 처리한다. 대기 시간 초과 시 클라이언트에 "잠시 후 재시도"를 돌려주고, 클라이언트가 자동으로 다시 보낸다.

3. **수정·삭제는 버전 검사**
   - 각 기록에 version 번호를 둔다. 수정 요청에는 읽었을 때의 version을 함께 보내고, 서버의 version과 다르면 저장을 거부하고 최신 내용을 돌려준다.
   - 화면에는 "다른 사용자가 먼저 수정했습니다. 내용을 확인 후 다시 저장하세요"로 안내.
   - 삭제는 실제 행 삭제가 아니라 deleted 표시(소프트 삭제)로 처리해 행 번호 밀림을 막는다.

4. **수정 권한은 작성자 본인만**
   - 기록은 작성자(또는 관리자)만 수정·삭제할 수 있다. 다른 교사의 기록은 읽기 전용이므로 수정 충돌 자체가 거의 생기지 않는다.

5. **클라이언트 보관함(outbox)**
   - 저장 버튼을 누르면 즉시 화면에 반영하고, 브라우저 저장소에 보관한 뒤 서버로 전송한다.
   - 전송 실패(네트워크 끊김, 잠금 대기 초과, 동시 실행 한도)는 지수 백오프로 재시도. 성공하면 보관함에서 지운다.
   - 같은 학생 화면을 다른 교사가 보고 있으면 새 기록이 들어왔을 때 "새 기록 N건" 표시 후 새로고침.

**알려진 한도 (배포 후 확인 필요)**
- Apps Script는 스크립트당 동시 실행 수에 제한이 있다. 100명이 정확히 같은 초에 저장하면 일부 요청이 "잠시 후 재시도"를 받을 수 있으나, 위 재시도 로직으로 유실 없이 처리된다. 정확한 한도 값은 배포 시점의 Google 문서로 확인한다.
- 시트 셀 한도(1천만 셀)는 하루 수백 건 기록 기준으로 수년 분량이 들어간다. 학년도별 시트 분리로 대응.

## 4. 로그인과 권한

작성자를 정확히 남기려면 사용자 식별이 필요하다. 학교 환경에 따라 두 방식 중 하나를 고른다.

| 방식 | 조건 | 장점 | 단점 |
|---|---|---|---|
| A. Google 계정 로그인 | 학교가 Google Workspace(교육용) 사용, 교사 전원 계정 보유 | 별도 비밀번호 없음, 작성자 자동 기록 | Workspace 없는 학교는 불가 |
| B. 교사 명부 + 개인 접속코드 | 관리자가 교사 명부 시트에 이름·코드 등록 | Google 계정 없어도 사용 가능 | 코드 분실 시 관리자가 재발급 |

역할은 두 가지로 둔다.
- **관리자(1~3명)**: 학생 명단 등록·수정·전출입 처리, 교사 명부 관리, 태그 관리, 전체 내보내기, 타인 기록 수정·삭제.
- **교사**: 학생 명단 조회, 기록 작성, 본인 기록 수정·삭제, 담당 학급 즐겨찾기, 본인 기록·담당 학급 내보내기.

열람 범위(전 교사가 전교생 기록을 볼지, 담당 학급만 볼지)는 확인 후 결정한다.

## 5. Google Sheet 구조

| 시트 | 열 |
|---|---|
| 학생 | id, 학년, 반, 번호, 이름, 메모, 상태(재학/전출/졸업), updatedAt, updatedBy |
| 관찰기록 | id, studentId, 날짜, 시간, 태그(쉼표 구분), 관찰내용, 조치·후속, 장소, 작성자, createdAt, updatedAt, version, deleted |
| 태그 | id, 이름, 색상, 순서, 사용여부 |
| 교사 | email 또는 코드, 이름, 역할, 담당학급, 사용여부 |
| 로그 | 시각, 사용자, 동작(추가/수정/삭제/내보내기), 대상 id |

- 관찰기록 시트는 학년도별로 나눈다(관찰기록_2026 등). 앱은 현재 학년도 시트를 기본으로 읽는다.
- 시트 편집 권한은 소유 계정만 갖는다. 교사에게는 시트 링크를 공유하지 않는다.

## 6. 개인정보 보호 조치

- 복지·상담·건강·문제행동 기록은 민감한 개인정보다. 시트 소유 계정은 학교 업무 계정으로 두고, 2단계 인증을 켠다.
- 앱은 HTTPS로만 접속. 브라우저 임시 저장소는 전송 완료 즉시 비운다. 공용 PC에서는 로그아웃 시 로컬 데이터 삭제.
- 모든 추가·수정·삭제·내보내기를 로그 시트에 남긴다.
- 학년도 종료 시 보관·파기 절차(내보내기 후 시트 보관, 앱에서 이전 학년도 숨김)를 관리자 메뉴에 둔다.
- 학교 개인정보 보호 내부 지침과 맞는지 배포 전 담당자 확인을 권장한다.

## 7. 기능 목록

### 1단계 (필수)

**학생 명단 관리**
- 관리자: 학생 추가·수정, 명단 일괄 붙여넣기(시트에서 복사한 TSV), 전출입·졸업 상태 처리
- 교사: 학년·반별 목록, 이름 검색, 담당 학급·관심 학생 즐겨찾기(교사별 개인 설정)
- 학생 삭제 대신 상태 변경으로 처리해 기록 보존

**관찰기록 작성 창**
- 학생을 누르면 바로 열리는 입력 화면. 날짜·시간 자동 입력
- 태그 복수 선택, 관찰 내용, 조치·후속 계획(선택), 장소·상황(선택)
- 저장 즉시 화면 반영, 실패 시 자동 재전송(3절 참고)
- 같은 화면에서 이전 누가 기록 확인. 다른 교사 기록은 작성자 이름과 함께 읽기 전용 표시

**태그**
- 기본: 복지, 상담, 건강, 학습, 문제행동, 기타
- 관리자가 추가·이름 변경·색상·순서 변경. 태그별 기록 수 표시
- 교사별 최근 사용 태그 우선 표시

**기록 조회**
- 학생별 타임라인(최신순), 태그·기간·작성자 필터, 본문 검색
- 내 기록 / 전체 기록 전환, 오늘·이번 주 기록
- 작성일·수정일·작성자 표시

**내보내기·백업**
- TSV: 학생·날짜·태그·내용·조치·작성자 열. 교사는 본인 기록·담당 학급, 관리자는 전체
- Markdown: 학생별 관찰 보고서(태그별 소제목, 날짜순)
- 시트 자체가 원본이므로 별도 JSON 백업은 불필요. 관리자 메뉴에서 시트 사본 생성 안내

### 2단계 (선택)

- 대시보드: 학생별·태그별 기록 수, 최근 30일 추이, 기록이 오래 없는 관심 학생
- 후속 조치 관리: 조치 완료 체크, 미완료 목록, 담당자 지정
- 상담·연계 요청 초안: 특정 학생의 태그별 기록을 모아 의뢰 문안 생성
- 사진·파일 첨부(Google Drive 폴더에 저장, 링크만 시트에 기록)
- Notion 연동(선택)

### 3단계 (추후 검토)

- 생기부 행동특성·상담일지 문안 초안
- 학부모 상담 기록 연동

## 8. 화면 목록 (디자인 작업용)

1. 로그인 화면
2. 명단 화면: 검색창, 학년·반별 목록, 즐겨찾기, (관리자) 학생 추가·일괄 추가
3. 학생 상세 화면: 학생 정보, 빠른 기록 입력 폼, 태그 칩, 누가 기록 타임라인, 필터, 새 기록 알림
4. 기록 작성·수정 모달 (충돌 안내 상태 포함)
5. 전체 기록 화면: 내 기록·전체, 오늘·이번 주, 태그 필터
6. 내보내기 화면: TSV, Markdown
7. 관리자 화면: 학생 명단 관리, 교사 명부, 태그 관리, 로그, 학년도 관리
8. 전송 상태 표시: 저장 중 / 저장 완료 / 재시도 대기 / 충돌

휴대폰에서는 명단 → 상세가 한 화면씩 넘어가고, PC에서는 좌우 두 칸으로 배치한다.

## 9. 개발 순서

1. 시트 구조와 Apps Script 백엔드: 읽기·추가·수정·삭제 API, 잠금, 버전 검사, 중복 ID 무시, 로그
2. 로그인·권한 처리 (A 또는 B 방식)
3. 프론트 데이터 계층: 보관함(outbox), 재시도, 충돌 처리
4. 명단 화면, 학생 상세·기록 작성, 태그
5. 조회·필터·검색, 내보내기
6. 관리자 화면
7. 동시 저장 부하 테스트 (같은 학생에 다수 요청 동시 전송 → 유실·중복 0건 확인)
8. 디자인 적용, 반응형 정리, PWA
9. (2단계) 대시보드, 후속 조치, 첨부

## 10. 확인이 필요한 사항

1. 학교가 Google Workspace(교육용)를 쓰고 교사 전원이 계정을 갖고 있는가? (로그인 방식 A/B 결정)
2. 기록 열람 범위: 모든 교사가 전교생 기록을 볼 수 있는가, 담당 학급·학년만 보는가?
3. 관리자 역할을 맡을 사람(명단·교사 명부 관리)이 정해져 있는가?
4. 학생 명단 초기 등록 형식: 나이스·엑셀에서 내려받은 파일을 붙여넣는 방식이면 되는가?
